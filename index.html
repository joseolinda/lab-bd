A conexão falhou?
  • password authentication failed: confira o usuário completo e a senha PostgreSQL.
  • permission denied for database postgres: em Properties → Connection, troque Maintenance database pelo seu banco.
  • could not translate host name / connection refused: confira postgres, a porta e chame o professor para verificar os serviços Docker.
  • Vejo nomes de outros bancos: a listagem pode mostrar nomes, mas isso não dá acesso a eles. Abra somente o seu.

Missão 03 / 10 · 10 min

Dê um lugar à sua escola.

Um banco contém schemas. Um schema organiza tabelas e outros objetos.

Servidor PostgreSQL → aluno_nomealuno → schema escola → tabelas

Seu banco pessoal já existe. Agora criaremos o schema escola dentro dele. No PostgreSQL, um banco não fica dentro de outro banco. Sua conta foi preparada para trabalhar no seu banco e não possui permissão para criar novos bancos.

  1. Expanda Databases → aluno_nomealuno.
  2. Clique com o botão direito em Schemas → Create → Schema….
  3. Na aba General, digite escola em Name.
  4. Em Owner, mantenha sua própria role: seu_usuario.
  5. Clique em Save. Se o objeto não aparecer, clique com o botão direito em Schemas → Refresh.
  6. Expanda escola e localize a coleção Tables. Ela ainda estará vazia.
Por que não usar public?

public é um schema que já vem no banco. Nesta atividade, escola mantém os objetos da escola organizados em um lugar próprio. Os dois são schemas, não tabelas.

Missão 04 / 10 · 10 min

Da modelagem para as tabelas.

A escola oferece turmas regulares e oficinas. Cada turma representa uma oferta em um ano letivo.

As regras deste pequeno projeto

  • Um aluno pode participar de várias turmas, e uma turma pode receber vários alunos.
  • Cada matrícula liga um aluno a uma turma.
  • O mesmo par aluno–turma só pode aparecer uma vez nas matrículas.
  • O nome de uma pessoa pode se repetir. O identificador da linha não pode.

É um recorte didático de uma escola. Ele será ampliado em outras aulas.

Traduza cada escolha

integer

Números inteiros: identificadores e ano letivo. Deixe Length/Precision vazio.

character varying(n)

Texto com até n caracteres. Também chamado de varchar. Escolha o tipo e preencha o tamanho no campo próprio.

date

Data de calendário. A apresentação visual depende do idioma e das preferências.

Not NULL

Impede um valor nulo. Não garante, sozinho, que um texto tenha conteúdo: uma string vazia é diferente de NULL.

Primary key · PK

Identifica cada linha; não permite duplicidade nem NULL. Nesta aula, os ids são inteiros manuais: marcar PK não gera números automaticamente.

Foreign key · FK

Exige que a referência corresponda à chave indicada na outra tabela. A obrigatoriedade será definida também com Not NULL.

Vamos criar turmas e alunos primeiro. Depois, matriculas poderá referenciar as chaves que já existem. Use nomes em minúsculas, sem espaços e sem acentos.

Missão 07 / 10 · 25 min

Ligue alunos e turmas.

Ter uma coluna chamada aluno_id não cria um relacionamento. Vamos definir as chaves estrangeiras.

1. Crie a tabela matriculas

  1. Em escola → Tables → Create → Table…, preencha Name: matriculas, Schema: escola e mantenha sua role em Owner.
  2. Em Columns, adicione as quatro linhas abaixo e clique em Save. Deixe os valores padrão vazios.
Ficha de criação · escola.matriculas
NameData typeNot NULL?Primary key?
idintegerSimSim
aluno_idintegerSimNão
turma_idintegerSimNão
data_matriculadateSimNão

2. Adicione a referência ao aluno

  1. Expanda matriculas. Clique com o botão direito em Constraints → Create → Foreign key….
  2. Em General → Name, digite fk_matriculas_aluno.
  3. Na aba Columns, escolha Local column: aluno_id, References: escola.alunos (tabela alunos do schema escola) e Referencing: id.
  4. Clique em + / Add para incluir o par na lista. Selecionar os campos sem adicionar o par não conclui a definição.
  5. Na aba Action, mantenha On update: NO ACTION e On delete: NO ACTION. Deixe as outras opções no padrão e clique em Save.

3. Adicione a referência à turma

Repita Constraints → Create → Foreign key…, desta vez com:

CampoValor
General → Namefk_matriculas_turma
Columns → Local columnturma_id
Columns → Referencesescola.turmas
Columns → Referencingid
Action → On update / On deleteNO ACTION / NO ACTION

Adicione o par com + / Add e salve. As duas FKs devem aparecer em matriculas → Constraints.

O que as FKs asseguram?

Nas futuras matrículas, aluno_id e turma_id deverão apontar para registros existentes. Com NO ACTION, uma alteração ou exclusão de chave que deixaria matrículas sem referência será recusada. As FKs não copiam os nomes nem cadastram alunos ou turmas automaticamente.

4. Impeça a matrícula duplicada

  1. Em matriculas → Constraints, clique com o botão direito e escolha Create → Unique constraint.
  2. Em General → Name, digite uq_matriculas_aluno_turma.
  3. Em Definition → Columns, selecione aluno_id e turma_id na mesma restrição. Deixe as outras opções no padrão e clique em Save.
  4. Confira em Constraints: uma PK, duas FKs e uma UNIQUE.
A combinação é única.

UNIQUE(aluno_id, turma_id) permite o aluno 1 na turma 1 e na turma 2. Também permite alunos diferentes na turma 1. Ela impede repetir o par (1, 1). Duas regras UNIQUE separadas impediriam essas participações legítimas. Not NULL continua sendo uma configuração própria das duas colunas.

Já existe a combinação aluno 7, turma 2. Qual nova combinação a UNIQUE composta bloqueia?

Minha tabela de referência não aparece.

Confirme se alunos e turmas já foram salvas no schema escola do mesmo banco. Confira se cada uma tem PK em id e atualize a árvore. Em uma FK, a coluna local é a de matriculas; a coluna referenciada é o id da outra tabela.

Missão 08 / 10 · 7 min

A escola ganhou uma necessidade.

Precisamos guardar o e-mail de contato dos alunos. Vamos alterar a tabela que já existe.

  1. Em escola → Tables → alunos, clique com o botão direito em Columns → Create → Column….
  2. Na aba General, defina Name: email.
  3. Na aba Definition, escolha Data type: character varying e Length/Precision: 120.
  4. Na aba Constraints, mantenha Not Null: No e o valor padrão vazio. O e-mail é opcional e não será único neste exercício.
  5. Clique em Save e confira alunos → Columns → email. Use Refresh se necessário.

A tabela alunos continua sendo a mesma. Você acrescentou uma coluna à sua definição. Esse tipo de mudança pertence à DDL e corresponde a uma operação ALTER TABLE.

Missão 09 / 10 · 5 min

Crie e descarte um rascunho.

Vamos observar a remoção de uma estrutura usando uma tabela criada apenas para essa experiência.

  1. Em escola → Tables → Create → Table…, preencha Name: rascunho e confirme Schema: escola.
  2. Em Columns, adicione anotacao, tipo text, sem PK e com Not NULL? = No. Salve.
  3. Localize escola.rascunho na árvore. Confira o banco, o schema e o nome dessa tabela.
  4. Clique com o botão direito somente em rascunho → Drop. Leia o nome no diálogo e confirme a remoção normal. Drop (Cascade) é uma opção separada; use apenas Drop.
  5. Atualize Tables. Devem restar alunos, matriculas e turmas.
DROP remove a tabela.

Ele remove sua definição e também quaisquer dados que ela contivesse. Excluir uma linha e excluir uma tabela são ações diferentes. Aqui, somente a tabela descartável rascunho deve ser removida.

Ver exemplos de SQL equivalentes às ações da interface

DDL significa Data Definition Language, ou Linguagem de Definição de Dados. Observe os exemplos; a escrita e a execução manual serão trabalhadas depois. As ações abaixo já foram realizadas pela interface.

-- Criar uma estrutura
CREATE TABLE escola.turmas (
    id integer PRIMARY KEY,
    nome character varying(60) NOT NULL,
    ano_letivo integer NOT NULL
);

-- Modificar a estrutura existente
ALTER TABLE escola.alunos
    ADD COLUMN email character varying(120);

-- Remover a tabela descartável
DROP TABLE escola.rascunho;

O exemplo é uma explicação do que você fez. Não precisa ser executado novamente. O pgAdmin funciona como ferramenta; o PostgreSQL executa os comandos e mantém os objetos.
